# v0.7.22 现有功能的交互与稳定性打磨

本次迭代沿用现有命令、工作区和权限模型，没有增加运行时依赖、前端构建步骤或 AI SDK。版本号仍由发布标签注入；此说明随 PR 提交，不代表已经发布。

## 传输反馈

- 上传区分「发送到本机」「本机接收完成，等待远端确认」「写入远端」「完成」。浏览器发送到 100% 不代表远端写入成功。
- 队列持续显示阶段和错误详情，长文字换行；失败原因不会随提示消息消失。
- 断流、缺少最终结果、请求取消后都不会假定目标文件没有写入。取消后迟到的进度和成功消息不能复活任务。
- 确认覆盖期间取消不会继续上传；跨标签拖动下载仍使用原主机。

## 连接与监控

- 终端连接状态与监控读取状态分别显示。监控失败保留最后一次样本，并明确显示更新时间；超过 15 秒未更新会标记为旧样本。
- 切换主机清空监控错误和旧时间，断开显式连接显示「已断开」。较早的会话列表响应不能覆盖较新的列表。

## 文件与历史

- 显示读取状态，加载中不会误显示空目录。
- 目录与历史按最近请求更新；旧响应、旧错误、上一轮主机连接的目录树不会覆盖当前界面。
- 刷新相同目录保留仍存在的选中行和滚动位置；主机之间分别记忆。切换目录清除旧选中行。
- 文件修改和上传完成后的刷新仅针对仍在查看的原主机与目录。

## 终端

- 显式切换标签恢复终端焦点；后台连接完成不抢占其他标签或表单输入。
- 尺寸调整合并重复触发，复用 xterm 的尺寸变化通知，跳过隐藏或已关闭的终端。
- 限制 xterm 隐藏测量元素引起的页面横向滚动。中文输入与粘贴继续使用已有的 xterm 处理和 UTF-8 发送，不插入自动执行或重发逻辑。

## AI / 脚本调用结果

CLI `exec --json` 的每个 `results[]` 新增 `status`、`outcome`、`retrySafe`，原字段保留。网页命令结果也提供 `outcome` 和 `retrySafe`。

| 字段 | 含义 |
| --- | --- |
| `status` | CLI 执行结果：`ok` / `error` / `timeout` / `auth` / `connect` / `denied`；网页确认响应另有 `confirmation_required` |
| `outcome: completed` | 收到远端退出状态；仍需检查 `exitCode` 是否为 0 |
| `outcome: unknown` | 无法确认执行结果；超时或断线不能证明命令没有执行 |
| `outcome: not_started` | 网页执行入口在校验、拒绝或确认阶段返回，尚未执行命令 |
| `retrySafe: false` | 本工具不保证重放安全；非零退出也可能已经产生副作用 |

远端退出码 251 仍是 `status: error, outcome: completed, exitCode: 251`，不能只根据数字推断本地连接失败。网页的 `ok: true` 表示请求已处理，不保证远端命令成功。CLI 的顶层参数、配置或预检错误沿用原来的 `ok/error/code`，不属于 `results[]` 合约。

AI 应继续先用现有策略解释或执行预检；需要确认时交由人工完成。批量操作丢失响应后查询已有 `operationId`，记录过期、服务重启或 `unknown` 都不表示可以换 ID 自动重试。单命令入口阻止执行中重复点击，缺少完整结果时保留输入并提示核验；没有新增自动重试。策略、人工确认、出流限制和审计不会因为调用方是 AI 而放宽。

## Windows 与验证范围

- Windows 目录选择器明确按 UTF-8 输出路径，修复中文路径可能被旧代码页损坏的问题。
- 目录选择与打开目录测试使用 JSON 编码和解码，覆盖中文、空格和反斜杠。
- CI 新增原生 Windows 路径、操作去重、结果分类和 UI 回归任务；Linux 保留全量测试、OpenSSH 集成、安全扫描及六平台构建。
- 前端测试增加乱序响应、滚动恢复、传输阶段、取消、断流、重复提交、尺寸调整和 UTF-8 回归。
- Windows 原生任务是明确列出的测试子集。仓库全量测试仍有依赖 Unix 文件权限与模拟远端路径的夹具，不在本次声称的 Windows 全量通过范围内。

浏览器验证使用本机模拟主机和连接，检查真实 Alpine / xterm 资源、多标签焦点、中文与 16 KB 粘贴、目录恢复、深浅主题和窄屏布局；不替代真实服务器上的人工输入法、网络断连和大文件验收。
