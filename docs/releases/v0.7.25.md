# v0.7.25 传输队列与长时间使用优化

本说明随候选 PR 提交；源码版本保持 `dev`，正式版本由发布标签注入。复用现有 Alpine、xterm 和 SFTP，没有新增运行时依赖或前端构建步骤。

## 传输队列

- 文件区上传、拖入多批文件、下载和执行页上传共用一个页面内串行调度器。开始前显示等待项目，避免每批各自串行却跨批并行。
- 入队时固定主机、远端目标及下载目录；改变当前主机、路径或本地下载目录不会改变已排队项目的目标。
- 「取消」只停止此项；「整批」停止同批次的当前及等待上传项目，其他批次继续。尚未开始的任务释放队列持有的文件引用，不发请求。
- 等待身份或覆盖确认时取消，不会因为迟到的确认而重新发送。确认后重新发送，立即恢复传输中状态；此时取消仍需核验，不能误认为尚未执行。
- 执行页上传阻止重复提交，并保留等待期间修改的新输入。上传确认及 Bearer 验证继续走已有交互；只有明确未执行的身份/覆盖/策略挑战可以补充确认后重提，传输故障不会自动重试。
- 部分写入后的服务端错误明确返回 `outcome: unknown`，最终 NDJSON 失败消息也保留这一语义。

## 记录与进度

- 「清除已完成」和自动历史清理保留结果未知、请求取消后需要核验的记录。用户核验原主机和目标文件后，可以通过「核验」按钮解除保留；这不会重新执行或撤销传输。
- 最多保留 100 条普通结束记录；全部项目最多 256 条。执行中、等待中和待核验项优先保留，余量不足时拒绝整批入队，提示分批选择或先核验旧记录。
- 进度变化合并为每 100 ms 一次界面更新。最终结果和取消即时显示，并丢弃迟到进度，避免已经结束的项目重新变成活动状态。
- 文件名和进度行省略超长内容，悬停可查看完整名称、主机和目标。按钮保持稳定位置，错误说明仍可阅读。

## 终端输出

- 新页面通过 WebSocket `outputAck=1` 请求输出确认模式。服务端就绪消息的 `category: output_ack` 表示已启用；旧页面不请求时继续使用原协议，新页面连接旧服务端时也继续工作。
- xterm 消费二进制输出后，页面才发送 `output_ack` 和已消费的字节数。服务端限制未确认发送窗口为 256 KiB；窗口满后暂停 PTY 读取，让 SSH 现有流控减速生产者，不通过丢弃输出控制积压。另有现有的 32 KiB 读取缓冲和 SSH/网络缓冲；256 KiB 不是整个进程的内存上限。
- 确认消息不进入 shell，不计入用户输入。输入、窗口调整和输出确认由独立读取协程继续处理；断开时释放等待输出的协程。旧连接的消费回调不会向重连后的 socket 确认。
- 每个池内 SSH 连接共享一个关闭监听。即使输出窗口耗尽，SSH 关闭也会释放浏览器连接及桥接协程；正常 shell 退出仍通过原有输出读取路径结束，避免提前丢弃剩余输出。
- 浏览器后台或低性能设备消费变慢时，远端输出会相应变慢。这不改变 xterm 原有回滚历史长度，也不提供永久会话日志。

## 目录缓存

- 未展开子目录只保留目录引用，不再为宽目录里的每个子项创建空节点。展开时才创建节点；展开请求去重，折叠后迟到回复不会重新展开。
- 已读目录缓存以 32 个节点、8000 条目录引用为预算，淘汰较早分支，保留根目录和当前路径的祖先。被淘汰分支仍显示为可重新展开的目录。
- 工作区缓存最多 8 台主机，累计文件/目录引用以 16000 条为预算，优先保留最近主机。当前路径及最后一个工作区优先保留，因此极深或极宽的当前分支可能超过引用预算；这不是精确的堆字节上限。
- 合成场景：连续展开 20 个各含 2000 项的目录，缓存节点由 42,002 个降至 4 个，目录引用由 42,001 条降至 6,001 条。独立 Node 进程中强制 GC 后的堆增量约 13.5 MiB → 0.95 MiB，仅代表该缓存场景。

## 包体积

与已合并的 `a6870cc` 主线比较，相同 Go 1.27.2、Windows amd64、`CGO_ENABLED=0`、`-trimpath -buildvcs=false -ldflags '-s -w'` 构建：15,583,744 → 15,598,592 字节，增加 14.5 KiB，约 0.10%。对比排除了构建路径差异；测试和版本说明不进入运行时程序。

## 验证与边界

- 前端回归覆盖跨批调度、入队目标快照、取消准备中/等待中/已重新发送的任务、原生 DONE XHR 取消、迟到回调、待核验保留、进度合并、表单新输入和缓存淘汰。
- Go 合成 SSH 测试先暂停确认，验证输出停在窗口内，再恢复确认并验证 1 MiB 正文及输入后的标记完整有序。新增窗口阻塞/释放测试，并在 Linux CI 对输出流控运行 race 检查。
- 浏览器验证使用实际前端资源及模拟 API/通道，包括 8 MiB 输出消费期间输入送出，以及队列取消、保留和核验交互。模拟测试时长不代表真实网络吞吐。
- 队列和记录仍只在当前页面，刷新或关闭不能恢复任务；取消已发出的请求不等于撤销远端写入。真实弱网、后台节流、不同 SSH 服务端及实际大文件仍需环境验收。
