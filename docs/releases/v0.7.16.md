# 0.7.16：工作区布局与和命令行相同的传输

本版只改本机页面和它调用的传输入口。源码里的 `Version` 仍是 `dev`，发布号由 tag 经 ldflags 注入。没有新的运行时依赖。

## 工作区

- 文件表恢复横线（没有竖线），名称、大小、修改时间与横线对齐，单元格文字居中。名称格不再用 `display` 把表格单元格拆开。
- 左侧进程表的「命令」列占剩余宽度。长命令省略，悬停看全文，仍可点「详情」。
- 传输队列从文件区右侧移到左侧概况下面。概况不再画网络图，也不再显示「主机」「进程」「网络」这三行标题。主机名、指标、进程行和磁盘还在。
- 目录树固定从 `/` 展开。打开家目录时也会列出 `/` 的全部一级目录（`bin`、`etc`、`home`、`root` 等）。每一级只显示目录名，`/root` 显示为 `root`。

## 为什么 FinalShell 能下大文件，页面以前不能

FinalShell 是本机客户端，SFTP 直接写到磁盘，文件不经过浏览器。

0.7.15 的页面下载是另一条路：服务端已经按块从 SFTP 读出，但浏览器把所有块收进一个 `Blob` 再触发保存。这会占住与文件一样大的内存，所以当时把网页下载限制在 128 MiB，并提示改用命令行。上传则先把整个请求限制在 64 MiB（页面提示 63 MiB），再交给 SFTP。这两处都是浏览器路径自己的上限，命令行没有。

0.7.16 起，页面只负责状态和进度：

- 下载调用 `transfer.DownloadContext`，和 `ssh-cli download` 使用同一个 `transfer.Download`。文件写到本机目录，不进入页面内存，因此不再有 128 MiB 上限。默认目录是 `~/Downloads`（存在时），否则是 `~/ssh-cli-downloads`。传输队列里的「保存到」可填绝对路径，相当于命令行的 local 参数。目录会按目录树写到该目录下，不再在浏览器里打成 tar.gz。
- 上传仍由浏览器把选中的文件交给本机进程（网页拿不到真实路径），进程落到临时文件后调用 `transfer.UploadWithOptions`，和 `ssh-cli upload` 相同。去掉 63 MiB / 64 MiB 上限；超出 32 MiB 的请求体由 multipart 落到磁盘，不整段留在内存。

取消下载会关掉这次专用的 SSH 连接，和上传取消一样，不会拆掉旁边的终端。策略检查、确认和审计保持原样。
