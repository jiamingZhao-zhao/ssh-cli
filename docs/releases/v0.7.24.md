# v0.7.24 操作反馈与体量优化

此版本说明随候选 PR 提交；源码版本保持 `dev`，由发布标签注入正式版本号。本 PR 不合并、不打标签、不发布。

## 文件操作

- 新建、重命名、删除在弹窗打开时绑定原主机、目录、工作区代次及终端连接代次。提交前、策略确认后、Bearer 确认后重新检查；切换主机后再切回、改变目录、断开重连或离开终端页都会取消旧操作。
- 弹窗和请求共用忙碌锁，阻止重复打开和重复提交。已知未执行时保留输入和失败原因，可编辑后重试；结果未知时保留原主机和路径，先核验再清除提示，禁止直接重试。
- 成功返回实际路径，刷新原目录并选中新建或重命名后的文件。刷新失败不会把已完成写操作变成可重试的失败。迟到结果不会刷新另一台主机。
- 文件操作继续走原有策略、受保护路径解析、SFTP 校验和人工确认。客户端绑定不替代服务端校验。

## 单命令与结果缓存

- 单命令复用批量执行已有的 `operationId` 和结果查询接口。丢失回复、运行中、结果过期或中断时保持执行禁用，可查询原操作结果，或在核验远端后人工清除记录。
- 查询完成结果显示原主机、原命令、退出码及输出；不会清除等待期间修改的新命令。非零远端退出码仍属于已完成结果。
- 批量查询与单命令共用查询逻辑。缓存状态或结果正文为 `unknown` 时不会解除核验要求。
- 带编号的执行每个输出流最多 64 KiB，截断会明确标注。结果正文最多保留 32 条，编码后的总正文最多 8 MiB。超出数量或体积时淘汰旧正文，但在原 30 分钟时限内保留其请求摘要并返回未知，防止相同编号重新执行。
- 请求摘要最多 1024 条，同时运行最多 32 条；满时拒绝新操作。以上限制由当前进程内所有浏览器会话共享，结果读取仍按会话隔离。
- 完成记录从接收起最多保留 30 分钟；重启、过期、更换浏览器会话或正文淘汰后需要核验远端。编号不是跨重启的恰好一次保证；不要把 404、未知结果作为重放写操作的理由。

## 审计反馈

- 文件、命令、传输、历史和监控等已有审计写入点不再忽略落盘失败。JSON 使用 `auditWarning`，传输的最终 NDJSON 消息也携带该字段，终端通过控制帧提示。
- 远端结果与审计结果独立：远端成功而审计失败时保留成功、退出码及输出，同时显示警告；策略拒绝仍然拒绝。失败的审计不会自动补写，也不会重放远端操作。
- 池内会话关闭发生在 HTTP 请求之外；其审计失败会保留到进程结束，并在后续已授权 API 响应中提示。其他请求的成功不会消除这条缺失记录的事实。
- 警告内容不包含本地文件系统错误详情或凭据。关闭提示只影响当前页面提示；再次报告的失败仍会显示。

## 体量与界面

- 删除页面未引用的旧 `alpine.min.js`，保留正在使用的 Alpine CSP 版本。没有新增运行时依赖、前端构建步骤或组件库。
- 结果查询直接读取不可变缓存正文，减少重复分配；数量和编码字节数同时约束缓存。
- 修复离开终端后，xterm 的离屏字体测量元素撑出整页横向滚动条的问题。
- 本地相同 Go 1.27.2 和 `CGO_ENABLED=0`、`-trimpath -buildvcs=false -ldflags '-s -w'` 构建的 Windows amd64 程序，比主线基线小 33.5 KiB（15,612,928 → 15,578,624 字节），已排除构建路径差异。全部内嵌前端资源净减少约 36 KiB，按文件顺序合并后 gzip 比较净减少约 13 KiB；gzip 数据仅用于资源比较，不代表 HTTP 已启用压缩。

## 验证边界

新增回归覆盖原主机绑定、策略和 Bearer 二次确认、重复提交、失败输入保留、未知结果核验、迟到结果隔离、审计失败与远端结果独立、流式最终警告，以及缓存淘汰后不重放。SSH 测试使用本机合成服务器，不连接生产主机。

浏览器验证使用真实前端资源和模拟 API/终端消息；真实弱网、磁盘写满及浏览器重启恢复仍需实际环境验收。审计失败测试通过配置目录中的阻塞文件稳定模拟落盘错误。
