    Agent 调用示例

    下面是三种常见任务的调用顺序。重点是选准主机、执行前读策略，以及响应异常后先核验状态。

    只读检查主机状态

    显式指定 -H，减少默认主机带来的歧义；JSON 让 Agent 读取状态，而不是猜终端文本。

    此处是命令示例，不会执行远程操作。

    可以交给 Agent 的调用顺序
    ssh-cli host list --json
ssh-cli policy show -H demo --json
ssh-cli status -H demo --json
    目标明确 → 检查权限 → 读取状态 → 汇报结果
    SSH agent 身份

    SSH agent 可绑定公钥指纹；身份缺失时失败，不静默改用别的密钥。

    远端参数保留

    exec 保留分开的 argv，JSON 请求体与带空格参数不再靠 Agent 拼接猜测。

    显式连接复用

    显式启用 daemon 后可复用 exec 连接；普通调用不会自动启动或重试。

    默认行为与使用限制

    以下行为以 v0.7.31 为准。建议在接入脚本或 Agent 前确认，尤其是生产只读和人工确认要求。

    生产环境
    prod 默认上限为只读

    无限制交互终端在 readonly 下不可用；工具的文件操作仍检查权限和路径。

    危险命令
    目录默认不等于拦截

    需要启用并选择规则才生效；启用后默认作用于 prod，也可显式指定其他环境。

    人工确认
    确认门留给真实的交互终端

    非交互 Agent 不能用 --yes 绕过。standard/admin 的人工终端不逐条检查按键命令。

    本地审计
    能记录和核验，也有信任前提

    本地 HMAC 无法抵抗同时掌握签名密钥和日志的人；这不是独立的远端防篡改系统。
