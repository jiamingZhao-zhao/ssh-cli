查完机器，结果能对得上号

让 Agent 查磁盘后，能把结果对应到每台机器，并区分报错和结果还不确定的情况。

用起来的效果

汇报时，主机名、环境、执行状态和命令输出都有固定位置可读。

示例按 POSIX shell 书写，请先配好别名与登录方式。页面只展示，不执行。

只用 ssh / scp

ssh demo "df -h /"

Agent 能拿到输出文字和退出状态。要统一说明哪台机器、什么环境、有没有报错，需要再整理一层。

使用 ssh-cli

ssh-cli exec -H demo --json -- df -h /

加上 --json，结果就带有主机、环境和执行状态，命令输出也一并保留。Agent 可以按固定字段读取，再汇总给你。

还有哪些限制

工具只整理外层结果，磁盘数字仍是 df 的原文。收到执行结果，不等于命令成功，更不等于整个任务完成。

先准备登录信息

先登记主机别名和登录方式。工具支持私钥、SSH agent 和跳板；这些同样是 SSH 已有的能力。

服务器权限仍要管好

本工具只能检查经过它的操作。服务器账号仍需限制权限；持有凭据的其他程序可能绕过 CLI 直接连接。

连续调用需要提前设置

普通调用每次直接连接。要复用连接，需先启动 daemon 并用于 exec。OpenSSH 本身也有连接复用能力。

    接入前，先了解这些默认设置

    以下以 v0.7.31 为准。重点看生产环境、人工确认和本地操作记录，避免把工具提供的检查理解为所有风险都已解决。

    生产环境
    生产主机默认只读

    无限制交互终端在 readonly 下不可用；工具的文件操作仍检查权限和路径。

    危险命令
    危险命令清单默认未开启拦截

    先开启并选择规则，才会按这份清单拦截；启用后默认只在生产环境生效，可按需指定范围。

    人工确认
    需要人工确认时，非交互调用会被拒绝

    确认要在真实交互终端里完成，Agent 不能用 --yes 跳过。开放给人工的终端，仍需你自己判断输入的每条命令。

    本地审计
    记录保存在本机，重要结果需另外留存

    能同时修改记录和本地校验材料的人，仍可能破坏记录的可信度。重要场景需要独立保存记录，不能只依赖这一台电脑。

    安装与接入

    把仓库链接交给能读取仓库、执行本地命令的 Agent。它会准备 CLI 和 Skill，验证完成后，展示路径、版本与最短用法。
