密码与凭据

凭据在本机登记，Agent 调用只写别名

你输入一次密码，ssh-cli 加密保存。日常调用使用主机别名，不用反复把密码贴进对话或命令。

加密保存不等于隔离 Agent。以你的系统账号运行、能访问密钥和凭据的程序，仍可能取得密码。

加密、密钥和日志，分别保护什么？
密码文件
密码使用 ChaCha20-Poly1305 加密并校验完整性。配置只存引用；单独拿到配置或密码密文文件，不能直接读出密码。
主密钥
依次尝试系统凭据库、SSH_CLI_MASTER_KEY、本地 master.key。系统凭据库不可用而回退到文件时会提示。主密钥与密文同时泄露，仍可被解密；主密钥丢失后，已有密码也可能无法恢复。
使用与记录
主机列表不返回已保存的密码原文。审计和历史会尝试脱敏，但不能识别所有秘密；不要把密码写进远端命令或聊天。需要时也可选择私钥或 SSH agent，私钥认证同样是 OpenSSH 已有能力。

哪台主机做了什么，按记录核对

CLI 执行、上传、下载等按主机记下命令和结果。可启用 HMAC 完整性保护，核验记录是否被修改、删除或截断。

按主机记录，可启用完整性核验。

    示例日志已移除，保留的校验基线仍能发现缺失。

    ssh-cli audit verify --json
    示例记录未对应远端执行；三种校验结果由实际审计模块生成。点击只切换展示，不修改你的日志。
    本机保护不等于不可变存证：密钥被取得，或日志与校验基线一起回滚，超出本机校验边界。
    启用保护与写入保障
    首次 audit protect 由你在终端确认。可再启用审计不可写则拒绝新操作；重要场景把校验基线保存在独立可信位置。
    ssh-cli audit protect
ssh-cli audit configure --require-writable
ssh-cli audit list -g hunan-test --env test --source cli --json
    
      
    连续查几条命令，可以复用 SSH 连接
    同一主机的连接仍有效时，后续 exec 可复用它，减少重复握手和认证。每条命令的策略仍会重新检查。
    daemon serve → exec --daemon
    先单独启动 daemon，仅复用无需确认的 exec；默认调用仍为直连。

    日常任务Agent 直接用 ssh / scpssh-cli 提供的流程
    整理多机结果调用方整理主机身份、输出和退出状态。JSON 带主机、环境、结果状态，方便合并比较。
    替换远端文件自行安排备份、暂存和结果核对。暂存后提交；可选 --backup，传输结果带校验信息。
    响应中断调用方判断远端是否已执行。用 unknown 标记不确定结果，供核验；不自动重跑。
    多机检查自行组织并发和结果归属。exec 可显式并发，最多 4 台；仍整体检查策略。
    OpenSSH 也支持密钥、跳板和连接复用。这里的便利是把分类、检查、结果和审计接成一套 Agent 调用流程，不是每一项都独有。

      默认设置与使用边界    
      
      
      默认设置与使用边界
      以下以 v0.7.37 为准。CLI 策略、网页交互终端和本机凭据各有边界，接入前一起看清楚。
      
      
      生产环境
      生产主机默认只读
      CLI 执行和文件变更仍检查只读权限。网页交互终端按远端账号权限运行，终端内不逐条检查命令策略。
      危险命令
      危险命令清单默认未开启拦截
      先开启并选择规则，才会按这份清单拦截；启用后默认只在生产环境生效，可按需指定范围。
      人工确认
      需要确认的操作，无交互终端时拒绝
      你在自己的终端重新运行命令，按提示输入主机别名。聊天里回复“同意”不会自动放行。普通 exec 在交互终端允许 --yes；终端检查不能证明操作者一定是真人。
      本地审计
      记录保存在本机，重要结果需另外留存
      能同时修改记录和本地校验材料的人，仍可能破坏记录的可信度。重要场景需要独立保存记录，不能只依赖这一台电脑。
